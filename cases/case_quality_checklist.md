# Case Quality Checklist

Use this checklist before sharing a student-generated case with peers or an instructor.

## Clinical Clarity

- [ ] The clinical context is understandable to other students.
- [ ] The comparison is clear.
- [ ] The primary outcome is stated.
- [ ] The outcome type is identified as binary or continuous.

## Assumptions

- [ ] The standard-treatment or control value is stated.
- [ ] The expected novel-treatment value or clinically relevant difference is stated.
- [ ] The assumed effect is plausible enough for a teaching example.
- [ ] Alpha and power are stated.
- [ ] Expected dropout or missing data is considered.
- [ ] The source of the assumptions is described.

## Calculation

- [ ] The chosen calculation matches the outcome type.
- [ ] Required sample size per group is reported.
- [ ] Total required sample size is reported.
- [ ] Dropout-adjusted recruitment target is reported if relevant.
- [ ] Rounding is handled correctly.

## Interpretation

- [ ] The case explains what the calculated number means.
- [ ] Feasibility is discussed.
- [ ] At least one uncertain assumption is identified.
- [ ] The case mentions what could be changed if the required sample size is too large.

## Ethics And Reuse

- [ ] No identifiable patient information is included.
- [ ] The case can be understood without private local knowledge.
- [ ] If based on a real project, sensitive details have been removed or generalized.
- [ ] The student is willing to have the case reviewed for possible reuse, if applicable.


## Reasoning and simulation

- [ ] Goal and outcome/time point are explicit.
- [ ] Expected, planning and clinically important effects are distinguished.
- [ ] Sources, hypothetical status and plausible ranges are recorded.
- [ ] Equal allocation matches the implemented methods.
- [ ] Planning and generating assumptions, seed and B are saved.
- [ ] Interpretation covers zero, clinical threshold, width and feasibility.
